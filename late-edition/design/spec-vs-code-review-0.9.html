01 WHAT THIS IS

A code-aware re-read against the design package · not a re-design

Twelve code milestones in, the loop turns: a reporter ferries a lead to the Bureau, a photog ferries it to the Darkroom, the deadline fires, a story prints, and rivals can burn the press to the ground. This audit reads the v0.9 codebase against the four design HTMLs and the six ICDs, names every place the code drifts from the spec, classifies each finding, and hands Claude Code a prioritized fix list so the next architecture session and milestone 0.10 (Tier-0 closer) open from a known floor.

The methodology calls this a code-aware re-evaluation (METHODOLOGY §3 both halves) — the same shape as architecture/re-eval-after-0.3.md and architecture/re-eval-after-0.6.md, framed for the next handoff rather than as an in-tree session document. The roadmap's RE-EVAL after 0.9 slot is the formal landing site; this doc is the supplement that gets uploaded with it.

03 CRITICAL FINDINGS

Real bugs and contract drift · these block 0.10 or already break the loop
ID Sev Area Finding · Fix
C-01 critical Combat / Defense
Bureau HP never repairs between editions.

Design Doc §19 Press & production: "Press HP 90 · damaged by goon contact at 1/s · fully repaired between editions if > 0." The repair rule is the design's stated relief valve — a player who survives an edition gets the press back to 90 HP and the next raid is winnable.

Code: ackDebrief() applies heat decay and ticks rivals' onEditionEnd() but never touches bureau.hp. A 60 HP press at edition close stays 60 HP at edition open. Two unlucky editions in a row become a death spiral the design explicitly rejected.

Site: js/sim/world-state.js:434-447 (ackDebrief) — add bureau.hp = bureau.hp_max when bureau.hp > 0, after the heat decay line.
Test: add to tests/press-hp.test.mjs — damage Bureau partway, fire deadline, ack debrief, assert hp === hp_max. Add a second case: damage to 0 → game_over → debrief never opens → no repair.
ICD impact: none. Repair is sim-internal; ICD-01 §BuildingView hp projection unchanged.
C-02 critical Rival / Telemetry
raid_succeeded / raid_wiped digest events are never emitted.

The _buildEditionSummary projector filters _pendingRivalEvents by kind === 'raid_succeeded' to compute EditionDigestSnap.raids_succeeded, but only raid_attempted is ever pushed (_reconcileIntent, RAID_BUREAU branch).

Effect today: raids_succeeded in editionHistory is permanently 0, and the Evening Star's 3 consecutive failed raids → PANIC transition (ICD-02 §Evening Star state machine) will never fire even when its body lands at Tier-1 — it's reading from a counter that nothing writes. ICD-06 §EditionSummary's rival_events field is also missing the win/loss texture the debrief panel could surface.

Sites: js/sim/world-state.js — at the goon-damage tick (already deals damage), push {rival: 'evening_star', kind: 'raid_succeeded', text: '…'} when bureau.hp first crosses below hp_max in a raid window OR (cleaner) emit on the _enterGameOver path. At _pruneDeadUnits when the last living goon from a raid is removed, emit raid_wiped if no damage was dealt this raid.
Note: requires tracking "is a raid currently in flight" — likely a flag on EveningStar (e.g. activeRaidGoonsRemaining: number) or per-goon raid_id tag. Pick the lighter one and ICD-bump RivalsSnap in the same PR (Constraint #4).
Test: extend tests/evening-star.test.mjs + tests/goon.test.mjs — assert one raid_succeeded per raid that lands damage, one raid_wiped per raid where fixer kills all goons.
C-03 critical Game-end UX
Game-over overlay has no "new run" action.

ICD-04 §Notes (Saves after CYCLE_GAME_OVER): "the renderer mounts the THE PRESS BURNS overlay… and the only valid next action is 'new run.'" The "new run" affordance does not exist in js/game-over-overlay.js — the panel mounts a card with the kicker, banner, and reason text, then nothing. The player has to know to manually delete localStorage or open devtools to escape; refreshing the page lands them right back in the terminal state (the save round-trips the game_over: true flag verbatim, ICD-04 §Notes "round-trip integrity, not a feature").

Site: js/game-over-overlay.js:17-26 — add a button (<button class="new-run">Start a new run</button>) that calls storage.removeItem(SAVE_KEY) and location.reload(). Style under index.html's existing .gameover-card CSS.
ICD impact: none. UI affordance, not save-schema. ICD-04 §Notes already names this behaviour.
C-04 critical Core loop
No lead-spawn engine — the world holds exactly one lead, ever.

Design Doc §19 Leads: "1 lead per ~90s per district with a Bureau · ×1.5 with Tip Line · ×0.5 if no Bureau"; "Decay 3 minutes from spawn · halved if rival paper is nearby"; "Tier roll 70% Whisper · 25% Investigation · 5% Arc".

Code: World constructor spawns one hard-coded {flavor: 'vice', tier: 'whisper', tile: (2,2)} Story in 'lead' state. No spawner runs in tick(), no decay, no tier roll, no per-district rate. Once the player ferries it through, the four-ring loop spins dry — every subsequent deadline prints 0 stories and the debrief panel shows "(no stories printed)".

This is the load-bearing gap for milestone 0.10 ("5-edition arc · the first thing a friend can play"). Without a spawner, edition 2 onward is empty. ICD-05 v0.4.1 §Shape already supports everything the spawner needs to populate — no ICD-05 bump.

Site: new file js/sim/lead-spawner.js (pure module, mirrors resources.js / cycle-clock.js shape) with tickSpawn(world, dt) → Story[] + tier-roll table + decay rule. Wire into World.tick() after the rival tick but before cycle.advance. Constants medium-band per overview line 44.
ICD impact: potentially ICD-04 §Notes if spawn cadence needs its own RNG state (use the reserved rng_seed slot already on the save blob — see G-13 below).
Test: new tests/lead-spawn.test.mjs — spawn cadence under fixed-rng, decay clears expired leads, tier-roll distribution under a sample of 1000 spawns.
Coupled: requires districts (G-04) to honor per-district rates. A degenerate single-'d-default' spawner is acceptable as an intermediate step.
C-05 critical Edition rhythm
Debrief panel dismisses instantly — design says 30-second non-skippable pause.

Design Doc §19 Time: "Between-edition pause · 30s · cannot be skipped · debrief animation." Design Doc §05 The Core Loop: "The first 30 seconds of every new edition are a debrief — a literal stack of newspaper pages laid out on the corkboard."

Code: DebriefPanel mounts on EDITION_DEBRIEF_BEGIN and dismisses on any click into the panel root, immediately calling world.ackDebrief(). A player rapid-clicking can move through 5 editions in under 2 seconds. The debrief is the design's reward beat; making it skippable on the first click strips that.

ICD-06 §Cycle timing pins "Duration is player-controlled (click to dismiss)" — so the ICD wording disagrees with the design doc. This is an ICD-06 v0.3 → v0.4 amendment (§Cycle timing line edit), not a deviation; do it in the same PR as the code change per Constraint #4.

Site: js/debrief-panel.js — gate the click handler on a 30-second timer (setTimeout at _mount, set a flag, ignore clicks until then; show a "click to continue →" hint after the timer). World-side: ackDebrief stays player-driven, unchanged.
ICD impact: ICD-06 v0.3 → v0.4 §Cycle timing — change "Duration is player-controlled" to "30s minimum debrief animation; dismissable after the minimum elapses (Design Doc §19)". Authoring in same PR.
Test: tests/print-cycle.test.mjs — assert EDITION_DEBRIEF_END not emitted within 30 simulated seconds of EDITION_DEBRIEF_BEGIN; emitted on first click after.
C-06 critical Visual feedback
Rain never doubles at deadline. World-frame rain.intensity is hardcoded to 1.

Design Doc §12 Deadline UI: "At T-30s the strip turns bleed-red and the world's rain doubles." Design Doc §03 Rain: "Intensity ramps with edition pressure — by deadline minute zero, it is sheeting."

Code: snapshot() emits rain: { intensity: 1 } every frame unconditionally. The renderer (renderer.js) carries a constant RAIN_COUNT = 600 and does not read frame.rain.intensity — so even if sim ramped the value, the renderer wouldn't honour it. ICD-01 §WorldFrame declares rain: RainConfig with "intensity 0-1"; the field is wired through but dead at both ends.

Site (sim): js/sim/world-state.js:744 — compute intensity from cycle.remainingMs: 1 + (remaining ≤ 30_000 ? 1 - remaining/30_000 : 0) giving a 1→2 ramp in the last 30 s.
Site (renderer): js/render/renderer.js _stepRain — multiply per-frame line density (or visible-strip count) by frame.rain.intensity. Capping at 1500 lines is fine per Design Doc §15.
Coupled: design also says the deadline strip turns bleed-red at T-30s; HUD currently turns red at T-60s (js/hud.js:23 WARNING_MS = 60_000). See D-07.
C-07 critical Effects channel
WorldFrame.effects is permanently empty — no visual beats fire.

ICD-01 v0.5 §WorldFrame: "effects: FxEvent[] // flashes, prints, deaths" and §Notes: "effects: FxEvent[] is a drained queue — events live for one frame." The contract is authored; no producer exists.

Code: World initializes this.effects = [] in the constructor and the restore path. snapshot() drains it (this.effects.splice(0)) every frame. Nothing ever pushes. No flash on photog verify, no flash on print, no flash on goon kill or fixer death. The renderer doesn't even consume the array — the channel is dead from both directions.

Combined with C-06 (no rain ramp), the game has zero on-screen feedback for any state transition more transient than "a building took damage." The noir aesthetic is supposed to read by motion + light, not by HUD text. Without effects, every player action feels uncommitted.

Author: a small FxEvent vocabulary (lift from ICD-01 line 6: 'flash' | 'print' | 'death'; suggest also 'pickup' | 'verify' | 'raid_warning'). Push from _handleArrival (pickup/verify), _fireDebrief (print), _pruneDeadUnits (death), _reconcileIntent RAID branch (raid_warning).
ICD impact: ICD-01 v0.5 → v0.6 — add FxEvent union under §WorldFrame. Author in the post-0.9 paper slot, before code lands.
Renderer: per-event consumer in renderer.js — flash quads, paper-page sprite for print, etc. Scope per milestone (0.10 ships only what 0.10 needs).
Triage note for Claude Code. C-01 / C-02 / C-03 / C-05 are mechanical fixes (one file each, < 30 LOC, contained in one PR with the relevant ICD bump). C-04 / C-06 / C-07 are real design surface and should each open their own milestone slot. Recommended split: C-01 + C-02 + C-03 + C-05 into a "0.9.1 polish" PR; C-04 (lead spawn) into milestone 0.10's lead-spawner slot; C-06 + C-07 into a "0.10 visual feedback" PR after FxEvent ICD-01 v0.6 lands at the post-0.9 paper slot.

D-01 drift Unit balance
Photog walk speed 3.5 u/s vs. Design §19 spec 2.5 u/s.

Carryover from milestone 0.4 where Photog shipped at the Reporter speed. UNIT_SPEED table comment at js/sim/world-state.js:56-59: "photog 2.5 (held at 3.5 by carryover from 0.4 — re-tune at Tier-1 balance pass)."

Honest call; just needs to actually happen. Per design, photog should be the slower verifier paired with a faster reporter (§08 Photog: "Photogs are slow and skittish; pair them with reporters with high nerve") — the slowness is part of the dispatch puzzle.

Fix: change UNIT_SPEED.photog to 2.5. Update tests/unit-step.test.mjs if it asserts a specific traversal time.
D-02 drift Unit HP
Reporter, Photog, Editor have no HP fields.

Design Doc §19 Units: Reporter HP 2 · Photog HP 1 · Editor HP 2. Code: only Goon (HP 1) and Fixer (HP 3) carry hp / hp_max — the others use the makeUnit default which omits them.

Comment at js/sim/world-state.js:131 (Editor): "No HP — the Editor isn't a damage target at 0.7.1." True today (no source of damage on non-combatants). But: the design promises the Evening Star will BRIBE reporters (Tier-1), and a Photog walking through a raid is supposed to be jumpable. Without HP fields the damage-to-staff path has no shape.

Fix: add {hp, hp_max} to each unit at construction (js/sim/world-state.js:122-133). Plumb through UnitSnap already supports it (save.js:127-141). UnitView intentionally omits HP at v0.5 (sim-internal); no ICD-01 bump until a HUD surface needs it.
Scope: ship today; the damage source comes later. Schema-only change.
D-03 drift Resources
Cash / heat yields collapsed to midpoints — no ranges, no district modifier, no lie/front-page multipliers.

Design §19: "Story cash yield: Whisper $80–250 · Investigation $400–1200 · Arc $2000+ · all modified ±30% by district disposition." Code (resources.js): single midpoints (165 / 800 / 2000). "Heat: Vice +4–12 · Violence +6–18 · Money +8–22 · Lie multiplier ×1.5 · Front-page placement ×1.3." Code: single midpoints (8/12/15), no multipliers.

Comments acknowledge: "medium-band per overview line 44 · single representative per dimension, no district modifier, no lie/front-page multipliers. Those land at 0.7+ when districts and rival AI materialize." Districts have arrived (sort of — see G-04); the multiplier work hasn't.

Fix: couple to lead-spawner (C-04) — once Story carries a real district, add districtModifierFor(district, flavor) in resources.js. truthful: false ×1.5 heat multiplier is one line. Front-page placement requires a notion of placement (not modeled today; defer with the Story Engine §18 work).
Test: extend tests/resources.test.mjs.
D-04 drift Resources
Heat decay nuances missing — flat −8 only.

Design §19 Heat: "−8 per edition baseline · −12 if no controversial stories that edition · 0 decay if > 80." Code (resources.js): HEAT_DECAY_PER_EDITION = 8, applied unconditionally. Comment: "the −12 if no controversial and 0 decay if heat>80 nuances are medium-band balance refinements scheduled for 0.7+."

The "0 decay above 80" is what makes the heat curve dangerous near cap; without it the player can print a wild edition, ack debrief, and reset to manageable. The "−12 quiet edition" is the design's nudge to occasionally print clean.

Fix: in ackDebrief(), branch on summary.heat_applied > 0 for baseline-vs-bonus decay; clamp decay to 0 when resources.heat > 80 pre-decay. ~5 LOC. Tests in resources.test.mjs.
D-05 drift Rival AI
Goon spawn tile is hardcoded NW corner (0,0) — Design says "from district edges."

Design Doc §10 Defense Layer: "Goons appear from district edges, walk to the bureau." Code: GOON_SPAWN_TILE = { x: 0, y: 0 }, single point. Every raid walks the same diagonal across the 10×10 grid.

ICD-02 §Open questions (resolved at 0.7.0): "Multi-edition goon transit deferred to Tier-1 when district edges and patrol patterns enter the model." The spawn-tile question is part of the same deferral but worth flagging — visually it makes every raid look identical, which kills the "where are they coming from?" beat the HUD threats panel is supposed to surface (§13 mock: "3 GOONS · FROM SW").

Tier-0 fix: rotate among [(0,0), (9,0), (0,9), (9,9)] using the rival's RNG. Cheap, gets visual variety. Tag raid_attempted digest with the spawn corner so the HUD can render "FROM NW".
Tier-1 fix: real district edges once districts exist as data (G-04). Defer to Tier-1.
D-06 drift HUD
HUD warning threshold at T-60s, not T-30s as design specifies.

Design §12 Deadline UI + §19 Time: "At T-30s the strip turns bleed-red." ICD-06 §Cycle timing: "DEADLINE_WARNING fires once at T-30s." Code (js/hud.js:23-24): WARNING_MS = 60_000 (red strip), CRITICAL_MS = 10_000 (red + pulse).

The sim correctly fires DEADLINE_WARNING at T-30s (cycle-clock.js:13 DEFAULT_WARNING_MS = 30_000) but the HUD doesn't subscribe to it — it reads deadline_ms off HudState and picks its own thresholds.

Net effect: the visual escalation comes 30 seconds early. Not a bug, but a UX drift from the design's "the strip is calm until it isn't" beat.

Fix: change WARNING_MS to 30_000 in js/hud.js. Optionally drop CRITICAL_MS = 10_000 to 5_000 for tighter pulse window. One-line change + test.
Alternative: subscribe to CycleEvent events for the threshold transitions instead of polling deadline_ms — cleaner per ICD-06 §Subscriber expectations table.
D-07 drift HUD
Debrief panel is flat HTML — design calls for newspaper pages "laid out on the corkboard."

Design Doc §05: "The first 30 seconds of every new edition are a debrief — a literal stack of newspaper pages laid out on the corkboard, telling you what happened." §13: "the morning edition is a literal newspaper that lays itself out on the corkboard between cycles."

Code (js/debrief-panel.js): single card with kicker + banner + <ul> of story rows. The 0.9 PR's CHANGELOG calls this out: "the corkboard layout (Design Doc §13) materializes at milestone 0.9" — but 0.9 did the HUD corkboard around the viewport, not the debrief panel itself.

Combined with C-05 (instant dismissal), the debrief is the most under-delivered moment in the game today vs. its design intent.

Fix: milestone-shape work — give it its own polish slot inside 0.10 or stage as 0.10.1. Render StoryDigest rows as inline newspaper page cards (use existing Bodoni Moda + EB Garamond stack already loaded). Slap-down animation timed to the 30s pause (C-05). SFX-14 from audio-manifest already named for the page slap.
Scope check: straightforward CSS + DOM; ~150 LOC.
D-08 drift Save / persistence
SaveBlobV1.rng_seed always 0 — World has no top-level RNG owner.

ICD-04 §Notes Determinism: "The World-level RNG is reserved for systems that don't have a per-rival owner (lead spawn jitter at milestone 0.9+ is the first plausible caller)." Code (save.js:42): rng_seed: 0, // World RNG owner doesn't exist at 0.8; reserved for later.

The lead-spawn engine (C-04) is exactly the first plausible caller the ICD named. Add a SeededRng on World when the spawner lands; restore from blob.rng_seed on the snap path; serialize the live state at write. Existing tests (save-load.test.mjs) already lock the field; just needs to carry a real value.

Fix: couples to C-04 lead-spawner PR. this.rng = new SeededRng(opts.seed ?? Date.now() & 0xffffffff); on restore this.rng.state = blob.rng_seed. Update serialize() to read world.rng.state instead of literal 0.
D-09 drift Visual / Rendering
Lit windows, halftone print, fog-on-deadline ramp — none implemented.

Design §03 Material language: "Lit windows · Unlit emissive · ~40% lit at any time · flicker awake/asleep on a slow timer to suggest a living city." §03 Halftone print: "UI documents, photos, and the loading screen get a 3px-radius halftone treatment." §15: "FOG · Driven by a single uniform — by dialing the near plane we can ramp from damp to soup on deadline."

Code: buildings are simple toon meshes (buildBuildingMesh in renderer.js). No window quads, no flicker timer, no halftone CSS pass on the debrief panel, no fog-uniform dial.

None of these are blockers; they're the texture beats the design doc spent its visual-direction section on. The vertical slice survives without them, but a "feels like the doc" run does not.

Scope: renderer-side aesthetic polish; pick one or two for milestone 0.10 polish slot, stage the rest into Tier-1.
Easiest wins: lit windows (instanced emissive quads, ~80 LOC); fog-on-deadline (one-line lerp in apply()).
ICD impact: ICD-01 v0.5 §WorldFrame.fog already carries {near, far, color}; sim can dial near on the deadline ramp without an ICD change.
